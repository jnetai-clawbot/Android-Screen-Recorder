# Notes.txt — Android-Screen-Recorder

## What this is
A reliable Android screen recorder that records **video + audio** and captures **screenshots**, with a **floating quick-access bubble** overlay — like AZ Screen Recorder but built to be more dependable.

## Device compatibility
Works on **old AND new Android devices**:
- ✅ Samsung Galaxy S8 / S9 / S10, Note series, A series (Android 7–10)
- ✅ Google Pixel 6, 7, 8, 9 (Android 12–15)
- ✅ All Android 7.0+ (API 24+)

The app automatically handles the difference between old and new Android:
- **Old devices (Android 7–9):** requests storage permission so files save correctly.
- **New devices (Android 10+):** uses scoped storage / legacy external storage so files land in DCIM.

## ⚠️ DRM — read this (important, honest)
**DRM-protected apps (Netflix, Prime Video, Disney+, HBO Max, etc.) CANNOT be recorded.** Android uses Widevine DRM (L1/L3) which blanks the screen-capture frames at the **hardware / trusted-execution level**. No screen recorder can bypass this — it's enforced by the OS and the device hardware, and circumventing it is also illegal.

What this app DOES support:
- ✅ **Non-DRM streaming** — Twitch, YouTube (web/mobile, non-DRM), Vimeo, self-hosted streams, your own content, games, apps, calls, everything else.
- ✅ A **"Record streaming video (non-DRM)"** toggle in Settings to manage stream capture.
- ✅ If you try to record a DRM app, the video will come out blank/black — that's the OS enforcing protection, not a bug.

We will not add or support DRM circumvention — it's technically blocked and against the law.

## How to use
1. Install the APK, open the app.
2. Grant required permissions:
   - **Overlay** (Settings → bubble) — needed for the floating bubble
   - **Microphone** — needed to record sound
   - **Storage** (old devices only) — needed to save files
   - **Screen capture** — asked the first time you start a recording
3. Tap **"Show quick-access bubble"**.
4. Tap the bubble to expand it → shows buttons: **Record / Stop / Screenshot / Settings / Close**.
5. Record → red button. Stop → stop button. Screenshot → camera button.
6. Files are saved to:
   - Recordings: `DCIM/ScreenRecorder/Recordings/`
   - Screenshots: `DCIM/ScreenRecorder/Screenshots/`

## Settings (gear in bubble, or Settings screen)
- **Save location** — default `DCIM/ScreenRecorder`
- **Record audio with video** — toggle mic capture
- **Show screenshot button** — toggle screenshot option visibility
- **Record streaming video (non-DRM)** — manage stream capture
- **Resolution** — 720p / 1080p / 1440p / screen
- **Frame rate** — 24 / 30 / 60 fps
- **About** — made by jnetai.com, **Check for update** (links to latest GitHub release), **Share app**
- **DRM note** — explains why Netflix/Prime can't be recorded

## Version history

### v1.4.3 (2026-08-09)
- **FIXED EACCES storage error**: writing directly to the raw DCIM path is blocked by Android 10 scoped storage even with permission granted (legacy storage flag not honored on updated installs). Now records into the app-private external dir (always writable), then moves the finished file to the visible DCIM/ScreenRecorder/Recordings folder via MediaStore on stop.

### v1.4.2 (2026-08-09)
- **FIXED recording broken by v1.4.1**: MediaRecorder needs a real filesystem path, but v1.4.1 passed a MediaStore URI path (/external/video/media/...) which isn't a real path -> ENOENT. Now uses the real public DCIM/ScreenRecorder/Recordings path (visible in Gallery/File Manager) with requestLegacyExternalStorage.

### v1.4.1 (2026-08-09)
- **Recordings now save to a visible location**: on Android 10+ recordings are written to **DCIM/ScreenRecorder/Recordings** via MediaStore, so you can find them in Gallery / File Manager. They survive app crashes / battery death (written to disk immediately). Falls back to the app-private folder only if MediaStore is unavailable.

### v1.4.0 (2026-08-09)
- **Screenshot button is now a toggle**: tapping it shows/hides a small camera 📸 bubble. Tapping the camera bubble takes an instant screenshot (1 tap, no wasted time).
- **Tip overlay hidden by default**: the "Tip: DRM apps..." toast no longer shows on recording start unless you enable **Settings → Show tips** (new toggle, OFF by default).
- **Fixed "Create storage folders" error**: now falls back to the app-private external folder (always writable) if the DCIM path can't be created on Android 10 scoped storage.
- **Fixed Stop button**: the bubble's Record/Stop buttons now sync with the real recording state, so tapping Stop actually stops instead of starting a new recording.

### v1.3.9 (2026-08-09)
- **Fixed ENOENT storage error**: recordings now fall back to the app-private external folder (always writable) if the DCIM path can't be created on Android 10 scoped storage.

### v1.3.8 (2026-08-09)
- **Fixed SecurityException**: startForeground(mediaProjection) is now called BEFORE getMediaProjection().

### v1.3.7 (2026-08-09)
- **FIXED recording**: RESULT_OK is -1, which collided with the -1 sentinel in the check. Now checks data != null instead.

### v1.3.6 (2026-08-09)
- Service-side diagnostics for projection delivery.

### v1.3.5 (2026-08-09)
- **Diagnostic build**: added detailed logging to the screen-capture result callback so the error log shows the exact result code and whether projection data arrived. This pinpoints why recording isn't starting despite pressing "Start now".

### v1.3.4 (2026-08-09)
- **FIXED crash after pressing "Start now"** (`RemoteServiceException: startForegroundService() did not call startForeground()`). The projection data wasn't reaching the service via the intent extra, so it returned early without foregrounding → crash ~1 min later. The service now falls back to the statically-stored projection and always calls `startForeground()` even on the error path, so it never crashes.

### v1.3.3 (2026-08-09)
- **FIXED screen-capture permission never being requested** when tapping Start from the notification/bubble: MainActivity uses `launchMode="singleTask"`, so when the app was already open the capture intent went to `onNewIntent()` (which didn't exist) and was silently dropped. Added the `onNewIntent()` handler so the screen-capture prompt now appears and recording auto-starts on approval.
- **Auto-create storage folders** (ScreenRecorder/Recordings + Screenshots) on launch.
- Storage, microphone and notification permissions are still granted together in the single "Grant all" prompt on first launch.

### v1.3.2 (2026-08-09)
- **Storage location now shows a friendly folder name** (e.g. "DCIM/Screen-Recordings") instead of the raw `content://...` URI in Settings.

### v1.3.1 (2026-08-09)
- **FIXED bubble completely unresponsive to touch (drag/tap)**: there were two touch listeners fighting — one on the ImageButton (opacity) and one on the FrameLayout (drag/expand). The ImageButton was consuming all touch events before they reached the FrameLayout, so drag and tap-to-expand never fired. Removed the opacity listener from the button and made it non-clickable/non-focusable so the FrameLayout receives all touches.

### v1.3.0 (2026-08-09)
- **FIXED bubble not draggable / not expanding on tap**: the touch listener was on the bubble's FrameLayout, but the ImageButton inside it was intercepting the touch events, so drag and tap-to-expand never fired. The FrameLayout is now clickable/focusable so touches reach the drag/expand handler.

### v1.2.9 (2026-08-09)
- **Bubble opacity**: the floating bubble is now semi-transparent (55%) until you press it, then it becomes fully visible.
- **Notification bar controls**: the bubble's notification now shows **Start / Stop** buttons as a backup control (AZ-style), so you can start/stop recording from the notification bar even without touching the bubble.

### v1.2.8 (2026-08-09)
- **FIXED the actual crash when enabling bubble mode**: `ClassCastException: LinearLayout$LayoutParams cannot be cast to FrameLayout$LayoutParams`. The bubble button lives inside a `FrameLayout` (bubble_collapsed.xml) but the code set `LinearLayout.LayoutParams` on it, which crashed `FrameLayout.onMeasure` the moment the bubble was shown. Now uses `FrameLayout.LayoutParams` in both `createBubble()` and `refreshFromSettings()`.

### v1.2.7 (2026-08-09)
- **FIXED crash when enabling bubble mode**: the bubble service was adding the overlay window (`addView`) BEFORE calling `startForeground()`. On Android 14+ this can crash the service (ForegroundServiceTypeException / BadTokenException). Now `startForeground()` is called first, then the bubble is created.

### v1.2.6 (2026-08-09)
- **FIXED bubble not appearing on Android 14+**: the bubble foreground service was declared as `specialUse` type but the manifest was missing the `FOREGROUND_SERVICE_SPECIAL_USE` permission. On Android 14+ this throws a SecurityException, so the bubble service crashed instantly — no bubble and no bubble notification. Added the missing permission.

### v1.2.5 (2026-08-09)
- **Overlay bubble now shows immediately** when "Overlay bubble mode" is toggled ON in Settings (previously toggling it did nothing until restart). Toggling OFF hides it.
- **Fixed bubble crash on Android 14+**: Bubble service no longer uses the `mediaProjection` foreground type (which threw ForegroundServiceTypeException without an active projection).
- **Dark mode by default with light-green text** on the main screen, matching the Settings page.
- **New Diagnostics section in Settings** with an error log:
  - **View error log** — shows recorded errors/crashes
  - **Copy error log to clipboard** — one-tap copy to send to the developer
  - **Clear error log** — wipe saved entries
- Runtime errors (recording failures, projection/screenshot issues, permission problems) are now captured to the error log so you can see exactly what went wrong.
